# **混组体验拓扑搭建-需求分析**

## **原始需求**

根据今天下午会议讨论内容，混组体验拓扑搭建所需的TAUC信息可以先提供，需求细化如下：

1. 能覆盖9%、99.99% Network的组网设备台数（共两个数据）；
2. 在北美、欧洲、亚太地区，在组网设备台数 ≥10 台的 Network 中，需要以下数据：
   1. Network的拓扑图，包括组网方式（有线or无线）；
   2. Network中的具体机型（罗列每个Network中组网的设备名即可）；
   3. Network中无线组网设备的RSSI；
   4. 客户端Online数量最大时，所有客户端的类型（PC、Phone、IoT、NAS等）；
   5. 客户端Online数量最大时，所有客户端的分布情况（每个节点下关联了多少客户端）；

 

## **需求变更**

经沟通，TAUC当前会提供过去的指定七天内的订阅Qoe数据上报的网络的数据趋势分析

针对需求2提及的在组网设备台数≥10台的Network，根据初步调研，在有数据上报的网络中，最大拓扑为8ap，经协商一致会统计6ap及以上的所有数据，并分别绘制对应统计图标

具体地，根据当前数据上报及存储，

1. 针对需求2.a，仅提供每个ap跟上游ap的组网方式，无法提供组网拓扑结构
2. 针对需求2.b，仅能罗列具体机型，不能罗列组网设备的名称
3. 针对需求2.d，会依据Qoe上报规则，仅能显示有线客户端按Qoe上报字段X_TP_ClientType约定的客户端类型
4. 针对需求2.e，标明Controller对应数据

## **需求总结**

经沟通，TAUC当前会提供过去的指定七天内的订阅Qoe数据上报的网络的数据趋势分析

1. 能覆盖9%、99.99% Network的组网设备台数（共两个数据）随时间变化的折线图，提供Region，日期筛选框；
2. 在北美、欧洲、亚太地区，在组网设备台数≥6台的 Network 中，需要客户端 Online 数量最大时的以下数据，提供Network_id筛选框：
   1. Network的每个ap和上游设备的组网方式（无线组网的类型，eg. 2.4G，5G，2.4G+6G）；
   2. Network中的具体机型；
   3. Network中无线组网设备的RSSI（步长10dB）；
